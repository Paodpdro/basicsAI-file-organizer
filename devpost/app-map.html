Personal File Organizer — App Map

A small guide to where the scan, file reviews, and safe actions live.

What the app does

The Windows app scans six personal folders, suggests individual file moves, indexes purpose folders, and identifies possible duplicates or old files for review. You choose what to move, keep, or send to the Recycle Bin; the app does not silently change files.

This proof of concept uses local rules and file checks; it does not include an AI model or upload file contents for analysis. Purpose-folder names are saved locally in Electron’s user-data folder. PDF.js resolves CMaps and standard fonts from its installed package, and non-fatal warning-level messages are suppressed. The heading and body fonts are loaded from Google Fonts when available, with system-font fallbacks.

Follow one action: review a deletion candidate

One scan travels from Electron’s main process, through local candidate checks, to a review card in the window. Preview is separate from the Keep or confirmed Delete decision.

  1. Receive a scan request

    src/main/main.js — search for ipcMain.handle("folders:scan". It scans approved roots, builds move and deletion candidates, and returns metadata to the window.

  2. Check candidates and enforce safe decisions

    src/main/deletion-review.js — buildDeletionCandidates checks exact-content hashes and the one-year modified-time rule; createDeletionReviewQueue revalidates before Keep or Recycle Bin handling.

  3. Show the review and its result

    src/renderer/app.js — scanFolders receives the scan result, renderDeletionReview displays the paged cards, and each card handles Preview, Keep, or confirmed Delete. Safe previews are prepared by src/main/preview.js.

To change this, start here

Review labels or location layout

Start in src/renderer/index.html for the navigation labels; use renderMoveSuggestion in src/renderer/app.js for the compact path summary and expandable full paths.

Change deletion rules

Start in buildDeletionCandidates in src/main/deletion-review.js, then adjust the related cases in test/deletion-review.test.js.

Change colors or processing notices

Start in src/renderer/styles.css for decoration and status appearance, and setAppStatus in src/renderer/app.js for status wording and busy/error state.

A practice to reuse

This build caught a mismatch between a scanned file record’s path property and the duplicate sorter’s assumed filePath. A tied timestamp made the scan throw and blocked both review pages. The fix and the equal-timestamp fixture show a useful habit: test boundary cases in the real data shape, not just the common case. See “Deletion review” in devpost/prd.md and the duplicate test in test/deletion-review.test.js.

Run it again

In Windows PowerShell, from the synchronized Windows-side project copy (Windows does not launch npm with the WSL UNC share as its working directory):

npm install then npm start. Run the automated checks with npm test.
